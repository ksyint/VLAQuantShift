# 논문 초안 읽기

현재 논문은 **연구 질문과 실험 절차를 정리한 프로토콜 초안**입니다. 실제 VLA 모델의 실험 결과를 담은 완성 논문은 아닙니다. 제출용 영문 원고는 [shift_protocol.tex](shift_protocol.tex), 참고문헌은 [shift_references.bib](shift_references.bib)에 있습니다.

## 어떤 질문을 다루나?

**평소에는 성능이 유지되는 양자화 모델도, 카메라 관측이 달라지면 원래 정밀도의 모델보다 더 크게 성능이 떨어질까?** 이를 알아보기 위해 동일한 태스크와 초기 상태, 시드에 대해 아래 네 조건을 모두 실행하도록 설계했습니다.

| 조건 | 정책의 정밀도 | 입력 관측 |
| --- | --- | --- |
| FP clean | 배포된 체크포인트의 원래 정밀도 | 원본 관측 |
| Q clean | 양자화 | 원본 관측 |
| FP shift | 배포된 체크포인트의 원래 정밀도 | 사전에 정한 변화 적용 |
| Q shift | 양자화 | 같은 정의의 변화 적용 |

여기서 FP는 반드시 FP32를 뜻하지 않습니다. 기준은 해당 체크포인트가 배포된 정밀도입니다. `shift`는 밝기 증가, 잡음, 가림, 카메라 입력 제거처럼 **관측에 적용하는 변화**이며, 실제 물리 환경의 변화와 같다고 가정하지 않습니다.

에피소드별 성공 여부를 $Y$로 표시하면 비교값은 다음과 같습니다.

$$
e_{ji}=(Y^{\mathrm{FP},\mathrm{shift}}_{ji}-Y^{\mathrm{Q},\mathrm{shift}}_{ji})
      -(Y^{\mathrm{FP},\mathrm{clean}}_{ji}-Y^{\mathrm{Q},\mathrm{clean}}_{ji})
$$

$j$는 태스크, $i$는 매칭된 에피소드입니다. 태스크 안에서 에피소드 평균을 구한 뒤, 태스크마다 동일한 가중치로 다시 평균합니다.

$$
\widehat E=\frac{1}{J}\sum_{j=1}^{J}\frac{1}{n_j}\sum_{i=1}^{n_j}e_{ji}
$$

$100\widehat E$가 양수라면 관측 변화가 있을 때 양자화로 인한 성공률 손실이 더 커졌다는 뜻입니다. 단위는 퍼센트포인트(%p)입니다. 네 조건의 성공률과 clean·shift 각각의 정밀도 간 차이도 함께 보고해야 합니다. 예를 들어 shift 조건에서 FP와 Q가 모두 실패하면 이 비교값 하나만으로 문제를 드러내기 어렵습니다.

이 네 조건의 비교식 자체나 원고의 행동 차이 분해식을 새로운 이론으로 주장하지 않습니다. 논문으로서 차별성을 확보하려면 선행연구와 구별되는 재현 가능한 실험 근거가 필요합니다.

## 영문 원고에 담긴 내용

- **출처와 선행연구:** VLAQuantBench에서 가져온 부분과 새 확장 기능, 기존 연구와 겹치는 내용을 구분합니다.
- **실험 절차:** 동일한 에피소드의 네 조건 매칭, 관측 변화의 정의, 주 분석으로 제안한 조건을 설명합니다.
- **보정 데이터와 통계:** 보정·선택·평가 데이터 분리, 태스크 단위 부트스트랩, 여러 시드와 보정 데이터셋을 다룰 때의 제약을 정리합니다.
- **행동 차이 진단:** 외부에서 수집한 정책·상태 조합별 행동 배열을 분석합니다. 시뮬레이터 상태를 복원하고 분기해 자동 수집하는 기능은 아직 없습니다.
- **계획과 한계:** 모델·태스크·정밀도·관측 변화별 실험 계획, 결과를 채울 표, 논문 완성에 필요한 조건을 적었습니다.

## 실제 논문을 완성하려면

실제 모델 어댑터를 검증하고 체크포인트의 정확한 리비전, 태스크 목록, 양자화 대상 모듈, 관측 변화, 시드를 고정해야 합니다. 현재 제안된 주 실험은 LIBERO-Spatial의 $\pi_{0.5}$, 전체 모델 RTN W4, 평가 시드 0, `brightness:0.2`입니다. 이 밝기 변화는 각 uint8 RGB 채널에 $0.2\times255$를 더하고 범위를 잘라내는 방식입니다. 최종 실행 계획을 커밋하기 전까지는 확정된 사전등록이 아닙니다.

그다음 보정·선택·평가 데이터의 분리 조건을 충족하고, 매칭된 실제 모델 실험과 기준 방법 재현을 수행해야 합니다. 선택 데이터 목록과 태스크 단위 분리 검사 등은 아직 구현되지 않았습니다. VLABench 확장은 이후 단계이며, 초안의 결과 표에 있는 `Pending`은 측정하지 않았다는 뜻입니다.

현재 확보한 [검증 기록](../verification/README.md)은 테스트 180개 통과와 합성 데모 432 에피소드입니다. 원본 프로젝트의 417개 실험 조건은 별도로 점검한 기존 데이터입니다. 이 수치들은 새 VLA 모델의 성능, 실제 로봇 성능, 배포 속도 향상에 관한 결과로 사용할 수 없습니다.

원고는 인용 키 일관성을 확인했지만 TeX 도구가 없어 컴파일하지 않았습니다. 저자와 소속도 아직 확정하지 않았습니다. 자세한 구현 범위와 출처는 [UPSTREAM.md](../UPSTREAM.md), 실행 절차는 [저장소 README](../README.md)에서 확인할 수 있습니다.
