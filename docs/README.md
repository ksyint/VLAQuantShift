# 문서 안내와 용어 정리

처음이라면 [저장소 README](../README.md) → [연구 계획](shift_research_plan.md) → [관련 연구 검토](shift_related_work.md) 순서로 읽으면 됩니다. 현재 문서들은 `korean` 브랜치의 한국어 안내입니다.

## 용어부터 이해하기

| 용어 | 이 저장소에서의 의미 |
| --- | --- |
| VLA | Vision-Language-Action. 이미지와 언어 지시를 받아 로봇 행동을 출력하는 모델 |
| 양자화 | 가중치나 활성값을 더 적은 비트로 표현하는 방법. 실제 속도·메모리 이점은 구현에 따라 별도 측정 필요 |
| FP / Q | FP는 배포된 원래 정밀도, Q는 양자화한 정밀도. FP가 항상 FP32라는 뜻은 아님 |
| RTN | Round-to-nearest. 가까운 양자화 값으로 반올림하는 기준 방식 |
| W4 / W4A8 | 각각 가중치 4비트 / 가중치 4비트와 활성값 8비트 |
| 활성값(activation) | 모델이 입력을 처리하면서 중간에 생성하는 값 |
| 보정(calibration) | 소량의 데이터로 양자화 스케일·클리핑 등의 설정을 정하는 과정 |
| 과제(task) | 로봇이 수행해야 하는 목표. 같은 과제를 여러 초기 상태에서 반복 평가 |
| 에피소드(episode) | 초기 상태에서 시작해 성공·실패 또는 시간 제한까지 진행하는 한 번의 실행 |
| 폐루프(closed loop) | 행동으로 환경이 바뀌면 새 관측을 받아 다음 행동을 결정하는 실행 방식 |
| 행동 청크(action chunk) | 한 번의 추론으로 예측한 여러 시점의 행동 묶음 |
| 관측 변화(shift) | 평가 시 모델이 받는 이미지에 적용하는 변화. 현재 구현은 밝기·노이즈·가림·카메라 누락 |
| 짝 비교(paired comparison) | 같은 과제·에피소드·시드의 결과를 서로 연결해 비교하는 방식 |
| 실험 조건(cell) | 모델·정밀도·관측 변화·시드 등의 한 조합. 한 조건에 여러 과제와 에피소드 포함 |
| 실행 계획(manifest) | 실행할 조건, 출력 경로, 비교할 결과 파일 등을 명시한 JSON 파일 |
| 부트스트랩(bootstrap) | 관측한 표본을 다시 뽑아 통계량의 변동을 추정하는 방법. 여기서는 과제 단위로 재추출 |
| 체크포인트(checkpoint) | 학습된 가중치와 모델 설정. 저장소 이름만으로는 특정 가중치 버전이 고정되지 않음 |

## 행동 배열 분해를 사용하려면

이 기능은 네 개의 행동 배열을 이미 확보했을 때 사용합니다. `crossed-actions.npz`에 아래 키를 넣습니다. 각 배열의 모양은 `[T, D]`이며 T는 정렬된 유효 시점 수, D는 행동 차원 수입니다.

| 키 | 의미 |
| --- | --- |
| `fp_on_fp` | FP 정책이 방문한 상태/이력에서 FP 정책이 출력한 행동 |
| `q_on_fp` | 같은 FP 상태/이력에서 Q 정책이 출력한 행동 |
| `fp_on_q` | Q 정책이 방문한 상태/이력에서 FP 정책이 출력한 행동 |
| `q_on_q` | 같은 Q 상태/이력에서 Q 정책이 출력한 행동 |
| `scale` | 선택 항목. 행동 차원별 단위를 맞추기 위한 양수 스케일 |

```bash
vqs cross-replay crossed-actions.npz --out action-decomposition.json
```

입력에는 같은 시점, 행동 단위, 정책 이력과 의도한 난수 조건이 반영되어 있어야 합니다. 어느 한쪽의 에피소드가 종료된 뒤에는 유효 시점만 비교하도록 사용자가 먼저 정리해야 합니다. 분석기는 배열의 형태·유한한 값·대수적 분해를 확인하며, 시뮬레이터 상태 복제나 배열 수집의 적절성을 확인하지 않습니다. 이동·회전·그리퍼 차원을 무작정 더하지 말고 단위와 스케일을 명시하세요.

## 브랜치 사용하기

이미 저장소를 복제했다면 다음 명령으로 한국어 안내를 볼 수 있습니다.

```bash
git fetch origin
git switch korean
```

원래 구현과 영문 안내는 [main 브랜치](https://github.com/ksyint/VLAQuantShift/tree/main)에 있습니다. 한국어 브랜치는 명령 이름, JSON/YAML 키, 결과 데이터와 원본 출처를 바꾸지 않고 설명을 읽기 쉽게 정리합니다.
